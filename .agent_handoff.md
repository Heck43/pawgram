## 2. DevLog: Plugin System Exploration & Rollback (October 2026)

### 2.1 Context & Objective
The user requested researching and integrating a Python-based plugin system inspired by **exteraGram** (an Android Telegram client fork that had a Python modding engine using `.plugin` bundles).

### 2.2 What Was Built & Discovered
1. **exteraGram Reverse-Engineering:**
   - On Android, exteraGram ran CPython / Chaquopy embedded into the Dalvik/ART runtime.
   - Plugins used bytecode/dynamic hooking (`de.robv.android.xposed.XC_MethodReplacement`, LSPosed / SandHook) to intercept Java methods like `NotificationCenter.didReceiveNewMessages` and `MessagesController`.
   - On Windows Telegram Desktop, there is no Java runtime and no Dalvik VM. The client is native C++20 / Qt5 compiled with MSVC.
2. **Implementation Attempt:**
   - Embedded Python 3.11 runtime (`python311.dll`) loaded dynamically via `LoadLibraryW`/`GetProcAddress`.
   - Created `extera_sdk` Python module providing `BasePlugin`, `client_utils`, `ui.settings`, `ui.bulletin` (custom Win32 GDI animated capsule window).
   - Added settings UI in `settings_custom.cpp` with custom cards and modal dialogs using `Ui::GenericBox`.
   - Added outgoing command interception in `ApiWrap::sendMessage` (`dispatchSendMessage`).
   - Created demo plugin `hello_world.plugin` responding to `.hello`, `.hw`, `.привет` with text replacement and Win32 GDI bulletins.
   - Tested `.notify` and `.bulletin` commands in `in_app_notifications.plugin`.
3. **Critical CI Lesson Discovered:**
   - GitHub Actions workflow (`.github/workflows/build_custom_win.yml`, lines 100–145) **explicitly lists every file** to copy from the repository into the cloned upstream tdesktop folder via `Copy-Item -Force`.
   - If a C++ file is modified in the repo but not added to the `Copy-Item` list in CI, the build compiles with upstream vanilla code!
4. **User Feedback & Architecture Decision:**
   - The user tested the plugin build: test commands (`.hello`, `.notify`, `.bulletin`) worked as expected.
   - However, for chat messages, the user reminded:
     > *"ты наверное забыл, но для плагина мы нисколько не меняем внутренности клиента. все на внешней стороне"*
   - The user's requirement is that a plugin must not require modifying the internal C++ code of the client for each plugin, and must be purely an external mechanism.
   - Ultimately, the user decided to **completely rollback** the plugin system:
     > *"откати изменение до того момента, как мы начали делать систему плагинов"*
5. **Rollback Execution:**
   - Cleanly reverted commits `f7f23db` through `f98a73b` back to commit `2042b09`.
   - Revert commit `03807ae` was created and pushed to `origin/main`.
   - `git diff 2042b09 HEAD` is confirmed to be 0 bytes (exact match).

## 3. Critical Rules for Future AI Agents

1. **GitHub Actions CI Copy Step:**
   Whenever you add or modify any file in `Telegram/SourceFiles/`, check `.github/workflows/build_custom_win.yml` (lines 100–145). Every custom file **must be explicitly copied** using `Copy-Item -Force "$src\..." "$dst\..."`.
2. **Git Credentials:**
   Remote URL must remain clean `https://github.com/Heck43/pawgram.git` without hardcoded/expired tokens. Windows Credential Manager (`git:https://github.com`) handles authentication for `heck43`.
3. **Processes & Safety:**
   Always follow universal-modder rules: kill processes only by exact PID, do not delete user saves/data, and never commit build artifacts or decompiled third-party binaries to git.
